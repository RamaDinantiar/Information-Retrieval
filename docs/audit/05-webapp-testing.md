# Audit Pra-Deploy — 05 Uji Aplikasi di Browser

Hasil menjalankan aplikasi sungguhan di browser (Playwright, Chromium) terhadap **database MySQL lokal yang ada**, mencakup seluruh alur utama tiga peran. **Tahap ini hanya pengujian dan dokumen.** Tidak ada kode aplikasi yang diubah.

- **Basis:** `main` @ `caa6092` (setelah merge PR #11)
- **Lingkungan:** `http://ir-lab.test` (Herd), `APP_ENV=local`, MySQL `ir_lab`, antrean `database` dengan worker `queue:work` berjalan, `MAIL_MAILER=log` (email ditulis ke `laravel.log`, tidak ada pengiriman nyata)
- **Browser:** Chromium headless (Playwright, Python), viewport desktop 1366×850 dan ponsel 390×844. Satu mesin, satu browser.
- **Persiapan yang mengubah database lokal:** database lokal tertinggal satu migrasi (`2026_11_21_120000_create_reminder_logs_table`). Saya menjalankan `php artisan migrate` (aditif, tabel baru). Tidak ada `migrate:fresh`.
- **Penanda bukti:** **terverifikasi** = saya melihat hasilnya di browser atau database; **belum diuji** = lihat bagian 6.

## 1. Ringkasan

Alur utama berjalan dari ujung ke ujung: login, registrasi, reset password dengan OTP, gabung kelas dengan token, pembuatan tugas, pengumpulan berkas, penilaian, publikasi, laporan ngawas, verifikasi, ekspor Word dan Excel lewat antrean, Rekap Jam Ngawas (Tetapkan Final dan Buka Kembali), manajemen pengguna Admin, pembaruan langsung, dan penjaga sesi idle. Tidak ada galat JavaScript atau respons 5xx dari aplikasi selama pengujian.

Temuan yang perlu keputusan sebelum deploy:

1. **W1 (sedang, diperbaiki di branch `fix/pre-deploy`; uji di server dengan HTTPS):** setelah logout, tombol **Back** peramban menampilkan lagi halaman dashboard pengguna sebelumnya dari cache. Relevan karena praktikan memakai komputer lab bersama.
2. **W2 (rendah):** di ponsel, mode tinjauan nilai tidak memakai lebar penuh (ada kolom kosong di kanan).

Dua temuan lain bersifat pertanyaan kebijakan (W4, W6). Selain itu, tahap ini menutup tiga butir yang sebelumnya menunggu data nyata: **N8 aman di MySQL**, **waktu Tetapkan Final 1,34 detik** pada data lokal, dan **latensi pembaruan langsung 2,0 detik** (bagian 5).

## 5. Butir checklist yang kini punya data

- **N8 (Generate shift, MySQL):** dijalankan dua kali di dalam transaksi yang di-rollback pada 130 shift yang ada. Hasil: 0 shift baru di kedua kali, jumlah tetap 130, setelah rollback tetap 130. Pencocokan shift yang ada bekerja di MySQL; duplikasi hanya terjadi di SQLite. Catatan: ini membuktikan tidak ada duplikasi terhadap shift yang **sudah ada**; pembuatan dari nol di MySQL tidak saya uji agar data tidak berubah.
- **R3 (waktu Tetapkan Final):** **1,34 detik** untuk 4 asisten dan 1 laporan. Data produksi akan lebih besar; angka ini hanya batas bawah, bukan jaminan. Pengukuran ulang tetap perlu saat rekap nyata pertama.
- **S8 (pembaruan langsung):** dua sesi: perubahan muncul di sesi lain dalam **2,0 detik** (polling 5 detik). Beban dengan banyak pengguna tetap belum diukur.
- **Penjaga idle:** masa sesi 30 menit, peringatan muncul di menit ke-28 (2 menit terakhir), keluar otomatis ke `/login?expired=1`.

## 6. Yang tidak diuji

- **Pengiriman email nyata** (SMTP). `MAIL_MAILER=log`, jadi email hanya diperiksa di log. Tautan verifikasi email dan tautan reset tidak diklik.
- **ClamAV** (`scan_status` selalu `clean` di lokal).
- **Membuka berkas di Word dan Excel.** Isi ZIP, `document.xml`, sheet, dan nama sheet diperiksa lewat XML; tidak dibuka di aplikasinya.
- **Peramban lain:** hanya Chromium. Safari, Firefox, dan Chrome ponsel sungguhan tidak diuji. Mobile adalah emulasi viewport.
- **Alur yang tidak dijalankan:** tukar shift, kehadiran dan sesi, kontrak kursi dan denah ruangan, modul Program, pembuatan pengumuman, pengaturan kelas, unggah foto profil dan tanda tangan, ubah password dari profil, pencarian global, tandai notifikasi dibaca.
- **Aksesibilitas** (pembaca layar, kontras, navigasi papan ketik) dan **kinerja di bawah beban**.
- **Server produksi:** `TRUSTED_PROXIES`, HTTPS, header HSTS, dan pelambatan IP perlu diuji setelah deploy (lihat checklist).
